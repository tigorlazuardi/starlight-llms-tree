Static build emits Markdown next to HTML output. Every published docs page gets endpoint based on final public route. Every folder containing pages or child folders gets `llms.txt`.

### I/O examples

Source routes:

```text
/
/guides/
/guides/install/
/reference/api/
```

Build output with `base: '/docs'`:

```text
dist/index.md
dist/guides.md
dist/guides/install.md
dist/reference/api.md
dist/llms.txt
dist/guides/llms.txt
dist/reference/llms.txt
```

Root index links direct pages and child folders. Each child index repeats same rule for its own direct pages and folders, so traversal is generic at any depth:

```md
# Docs

## Folders

- [Guides](/docs/guides/llms.txt)
- [Reference](/docs/reference/llms.txt)
```

## Tags support

Tags classify pages by subject independently from URL structure. This lets an LLM client select a precise page using authored metadata instead of guessing from titles and paths.

Allow `tags` in your Starlight content schema:

```ts
import { defineCollection, z } from 'astro:content';
import { docsLoader } from '@astrojs/starlight/loaders';
import { docsSchema } from '@astrojs/starlight/schema';

export const collections = {
  docs: defineCollection({
    loader: docsLoader(),
    schema: docsSchema({
      extend: z.object({ tags: z.array(z.string()).optional() }),
    }),
  }),
};
```

Then add complete tags to page frontmatter:

```md
---
title: Install
description: Install on supported platforms.
tags: [setup/linux, setup/mac]
---
```

Generated page entry preserves those tags:

```md
- [Install](/docs/guides/install.md): Install on supported platforms.
  - Tags: `setup/linux`, `setup/mac`
```

## Scope hoisting

Scope hoisting makes topic discovery cheap at every tree level. Client can reject irrelevant folders from parent `llms.txt` instead of fetching every nested index first.

Plugin derives scope from text before first `/`; tag without `/` is already complete scope. It collects scopes from every page below a folder, removes duplicates, sorts them, then adds them to parent folder link.

Given pages below `guides/` tagged `guide`, `setup/linux`, and `setup/mac`, generated parent index contains:

```md
- [Guides](/docs/guides/llms.txt)
  - Scopes: `guide`, `setup`
```

Client sees `setup` at parent level, follows `guides/llms.txt`, then uses full `setup/linux` and `setup/mac` tags to select page. This preserves detail at leaves while exposing compact routing hints above them, regardless of tree depth.

Page endpoint starts with JSON frontmatter copied from Starlight metadata, then normalized readable Markdown. Generated links target `.md` endpoints and `llms.txt` indexes. Draft pages, 404 page, redirects, and non-doc routes are excluded.

Do not create files named `llms.txt` or generated `<route>.md` paths in static output; collision stops build without partial generated artifacts.
